# トースターでパンを焼いて食卓まで運ぶロボット

## 1. タスクの概要と目的

Pi0.5 は、カメラ画像と言語の指示からロボットの行動を出力する VLA（Vision-Language-Action）モデルである。LeRobot の公開チェックポイントは、家庭のキッチンを模したシミュレーション環境 RoboCasa には対応していない。
本作業では、RoboCasa のタスク GetToastedBread を追加学習し、タスクに適用させることを目的とした。

| 項目 | 内容 |
|---|---|
| **内容** | トースターのレバーを押して作動させ、レバーが上がる（ポップアップ、作動から 25 秒後）のを待ってから、パンをダイニングカウンターの皿に置いて手を離す。「押す → 待つ → 取り出す → 運ぶ → 置く」の順序を守る必要がある長いタスク |
| **成功条件** | ① パンがスロットに入った状態で、レバーを可動域の 90% 以上まで下げて作動させる　② パンが皿に接し、皿の中心から一定の距離内にある　③ グリッパーがパンから 25cm 以上離れている |
| **ロボット・入出力** | 移動台車付きのロボットアーム。入力はカメラ 3 台（256×256）、状態 16 次元、指示文。行動は 12 次元 |
| **起点モデル** | `lerobot/pi05_base`（RoboCasa 向けの学習がなく、RoboCasa の入出力も持たない） |
| **学習データ** | 人間のデモ 506 本 / 654,840 フレーム（50 タスクの統合データセットから抽出） |
| **評価** | 50 本（seed 1000〜1049。キッチンの配置が毎回変わる）。上限 2000 step（20 fps で 100 秒）。最終モデルは 3600 step でも評価 |

## 2. 工夫した点

成功判定だけでは、どこまでできていて何が足りないかが分からない。そこで、タスクのどの段階まで進んだかを記録する診断を作り、足りない能力を特定しながら学習を進めた。

1. **入出力の対応付け**: pi05_base に RoboCasa の入出力と正規化を付与。1 タスク分のデータを抽出し、指示文をそろえる
2. **基本学習**: 506 本で 10000 step。パンは掴めるが、全工程は完了しない
3. **段階ごとの診断**: 足りないのはレバー操作と「押す → 待つ → 取り出す」の順序
4. 次の 2 つを試した
    - **A. レバーのデモを追加（成功せず）**: 作動はするが、その後パンを取り出せない
    - **B. 視覚記憶（MEM）（成功）**: 過去 5 秒の画像を入力。待ってから取り出し、皿へ運ぶ

- **① 入出力の対応付け**: `pi05_base` は行動・状態が 32 次元で、カメラ名も RoboCasa と違い、正規化の統計量も持たない。そこで、RoboCasa の入出力と統計量を付けた 0 step のチェックポイントを作り、学習の起点にした。また、統合データの task 文字列（タスク名）を評価時に環境が渡す自然文の指示に書き換え、学習と評価の入力をそろえた。
- **② 基本学習**（batch 32、10000 step、10 時間 59 分）: トースターの前まで移動し、パンを掴めるようになったが、全工程を完了したエピソードはなかった。
- **③ 段階ごとの診断**: 毎 step のシミュレータの状態（レバー位置、作動、ポップアップ、把持、皿との接触）から到達した段階を判定した。基本学習のモデルは 18/20 本でレバーを押し切れず、レバーを押さずにパンを取り出す例も多かった。レバーが上がってパンがスロットにある画面は、押す前とポップアップ後でほぼ同じに見えるため、現在の画像だけでは区別できないと考えた。
- **A. レバー操作のデモを追加**: レバーを押すだけのタスク TurnOnToaster のデモ 2,508 本を加えて学習した。レバーは作動させられるが、ポップアップ後にパンを取り出す例は出なかった。
- **B. 視覚記憶（MEM）**: LeRobot の Pi0.5 にある視覚記憶を有効にし、1 秒おきに過去 5 秒分の画像を入力した（追加パラメータなし）。4000 回更新したモデルは、50 本中 7 本でポップアップを待ってからパンを取り出し、**1 本（ep 36）が 1,803 step で全工程を完了して成功した**（図 1。標準の上限 2000 step 以内）。
- **課題**: 成功はまだ偶然に左右される（同じモデルを上限 2000 step で評価した別の回では 0 本）。焼いたパンを皿のすぐ横に置いた例が 3 本あり、置く位置がずれている。動作も遅い。

**図 1　MEM で追加学習したモデル（4000 回更新）が各段階まで進んだ本数（50 本中、上限 3600 step）**

| 段階 | 本数 |
|---|---:|
| レバーを押して作動 | 11 本 |
| ポップアップ | 11 本 |
| ポップアップ後にパンを掴む | 7 本 |
| 焼いたパンを皿へ運ぶ | 4 本 |
| **成功** | **1 本** |

段階は成功に必要な順に並べた。「焼いたパンを皿へ運ぶ」4 本のうち 1 本が成功し、3 本は皿の中心から 12〜15cm の位置に置いた。

## 3. 本タスクを通じて検証したこと

- **「操作して、終わるまで待つ」作業を記憶で扱える**: トースター、電子レンジ、電気ケトル、洗濯機など、今の画像だけでは「操作前」と「完了後」を区別できない家庭の作業は多い。追加パラメータなしで過去の画像を入力に加えるだけで、待ってから取り出す全工程を完了できた。
- **汎用モデルに新しい環境の作業を教えられる**: 入出力の対応付けと 1 タスク分のデモ（506 本）で、RoboCasa 向けの学習がない汎用モデルに、移動台車付きロボットの長い作業をさせられた。実機でも、テレオペレーションで集めたデモで汎用 VLA に新しい作業をさせる使い方に対応する。
- **段階ごとの診断は実機の評価にも使える**: 段階（操作、把持、運搬、配置）ごとの到達を記録すれば、足りない能力が分かり、手法を根拠を持って選べる。実機の試行は時間も費用もかかるので、シミュレーションで診断して方針を決めてから実機に移る使い方ができる。
- **制約**: 結果はシミュレーションだけのもので、実機では検証していない。成功は 50 本中 1 本で、動作もデモ（平均約 1,300 フレーム）より遅い。MEM の学習には GPU メモリ約 79GB が必要である。

## 4. 動画の構成

動画は、MEM で追加学習したモデルが GetToastedBread の全工程を実行する様子を示す（約 131 秒、20 fps）。

| 時刻 | 内容 |
|---|---|
| 0:00〜0:08 | トースターのレバーを押し下げて作動させる（8.5 秒） |
| 0:08〜0:33 | パンが焼けて、レバーが上がる（ポップアップ）のを待つ（33.5 秒） |
| 0:33〜1:28 | ポップアップ後、トースターからパンを掴む（87.9 秒） |
| 1:28〜2:01 | パンをダイニングカウンターの皿まで運んで置き（118.4 秒）、手を離して成功判定になる（120.8 秒） |
| 2:01〜2:11 | 成功後も 10 秒続け、パンが皿に留まり成功判定が続くことを見せる |
